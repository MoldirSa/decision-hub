CJM 2 — simplified signup and gated Create flow

Sprint 2 · 28 Sep – 2 Oct 2026 · one story · modules: Cabinet Registration + Cabinet Home / Documents / Flow

Copy this page into Jira as a single Story. Child items = Tasks. Balance Stripe and full cabinet navigation are out of this sprint.
Story

As a new organisation user
I want a short English signup that stores email, country and expected volume, then a sandbox that only unlocks Create flow after documents and a funded balance
So that we stop losing signups on legal-entity-only and missing CRM fields, without going live before documents are signed.

Outcome: every allowed-country signup writes email + country + expected_volume; Create flow is blocked until registration is complete, ≤5 country documents are accepted, and balance > 0.

Baseline (CJM 1 · current production)

Email → OTP → Company (volume already on this step) → Home with Create flow unlocked → Templates → Balance. Client type: legal entity only. ToS/DPA not separate links. No IP geofence before the form. No country document pack before Create flow. UI mixed RU/EN.

In scope / out of scope

In Sprint 2: registration delta, English copy on this path, client type allow-all, volume required for all countries, persist three fields, IP geofence, ToS + DPA as two links, sandbox first-run, country pack ≤5 docs, Create flow gate (including balance > 0 check).

Next sprint: Stripe top-up / ledger UX, full cabinet navigation after first-run, end-user SDK consent screens.

Story acceptance
  • Given an allowed country, when signup completes, org record contains email, selected country, expected volume.
  • Given Individual or Sole proprietor, when they submit client type, registration continues (no legal-entity-only block).
  • Given IP in US / EEA / UK / CH or a sanctioned territory, when they open register, the form is not shown and no org is created.
  • Given the password step, when they accept legal terms, Terms of Service and DPA are two separate clickable documents.
  • Given a country from the PUBLISH map, when they open Documents, they see at most 5 signing files for that country and must accept them before Create flow.
  • Given missing docs or balance = 0, when they click Create flow, the action is blocked and the sandbox shows the next required step (Documents or Balance).
  • Registration and this first-run path are in English.
Tasks inside this story
T1 · Registration

IP geofence + simplified English signup

Context: CJM 1 starts on the form; blocked countries learn late, on Company.

Goal: Do not start an account outside allowed territories; rest of signup is short and in English.

Implement: Geofence before the form (deny: US, EEA, UK, CH, sanctions → waitlist only). Screens: Email → OTP → Organisation → Password. UI English. After password: session into sandbox, no extra Sign in.

T2 · Registration

Required country + volume for every country; persist email + country + volume

Context: Volume already exists on CJM 1 Company step but is not a guaranteed CRM field for all countries.

Goal: Every allowed signup is qualifiable (email, country, volume in DB).

Implement: Country and Expected monthly volume required on Organisation, all allowed countries. Continue disabled until both set. Save on org create; expose in Admin API. Do not move volume into the cabinet.

T3 · Registration

Client type: allow all values

Context: CJM 1 blocks anyone who is not a legal entity.

Goal: Individual and sole proprietor can finish signup.

Implement: Keep the field required. Values: Legal entity, Individual, Sole proprietor — all continue. Remove the legal-entity-only stop.

T4 · Registration

Terms of Service and DPA as two links

Context: CJM 1 mentions documents in a hint, without two clickwraps.

Goal: Audit-ready accept of ToS and DPA as separate instruments.

Implement: Two checkboxes on Password, each with its own link (GLB01, GLB03). Store timestamp, IP, version, document id. Account is not created if either is unchecked.

T5 · Cabinet documents

Country signing pack, max 5 documents, before Create flow

Context: PUBLISH.zip has many files per country. Product shows only the signing set.

Goal: User signs the country pack before Create flow. Never more than 5 files.

Implement: Documents screen keyed by selected country. Fixed map (ToS + DPA + privacy + consent/notice; KG: cross-border consent; ID: language rider; KZ: End-User Terms + Verification Notice). Exclude opinions, checklists, tax, breach, DSR, DPIA. Accept all listed items; log version. Counsel confirms the map — this is a product list, not a legal opinion.

T6 · Sandbox

First-run home: checklist, Create flow gate, Balance button

Context: CJM 1 Home opens Create flow immediately.

Goal: Obvious path: finish profile → sign docs → fund balance → Create flow.

Implement: English sandbox checklist. Create flow disabled until (1) registration complete, (2) country docs accepted, (3) balance > 0. Show why it is blocked. Balance button visible. If docs missing → Documents; if balance 0 → Balance. Do not rebuild Stripe / ledger this sprint — only the gate and the CTA. Full sidebar navigation after first-run = next sprint.

Out of sprint · next backlog

Balance top-up UX + cabinet navigation

Stripe min/max, ledger, billing mode, and the rest of cabinet IA stay in the next sprint. Sprint 2 only needs the Balance entry point and the Create flow money gate.

Business rules
  • Source of truth for org: existing Cabinet organisation record. No second identity store.
  • Volume stays on registration, required for all allowed countries.
  • Client type never blocks signup in this sprint.
  • Create flow is not available without signed country pack and balance > 0.
  • Document lists are capped at 5 per country from the PUBLISH signing set.
Risks
  • US/EEA deny vs older Allow-Intl lists — confirm with Legal before production geofence.
  • Allowing Individual / Sole proprietor may change KYB / billing — Compliance to confirm.
  • 5-doc cap may omit a local consent file — Legal sign-off on the map.
  • Balance gate without Stripe UX may stall users — acceptable only if Top up CTA is visible.
